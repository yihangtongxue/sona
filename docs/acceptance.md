# 转录功能验收

以下由开发者执行。本次未启动应用、未运行测试、未下载真实模型；依赖锁文件已更新，但未安装新增依赖。

## 准备

在 Windows x64 与 Mac M5（原生 ARM64 Python）分别同步依赖并启动：

```sh
uv sync
uv run sona
```

Windows NVIDIA 路径需有兼容驱动；运行库由“模型设置 → 转录加速”按用户选择下载。应分别验收无 NVIDIA 显卡、有 NVIDIA 但未下载组件、组件已启用三种情况。MLX 仅需在 Mac 上安装，Windows 不应拉取 MLX / PyTorch 的 Mac 依赖链。

## 转录加速

1. 首次启动有 NVIDIA 的 Windows：设置页显示“下载并启用”和约 1.4 GiB 的下载大小；未点击时不请求 NVIDIA 下载地址，导入音频直接使用 CPU。
2. 无可用 NVIDIA 时显示“当前使用 CPU 转录”；驱动检测异常显示检查失败，不能误报“没有显卡”。Mac M5 显示 Apple 芯片加速，不出现 Windows 下载按钮。
3. 点击下载后核对进度、暂停和继续；断网显示失败并可重试，不能丢弃已经收到的有效部分。服务端忽略 Range 时应重新下载该文件，不能直接追加。
4. 下载中正常关闭或强制结束，再启动应停留在暂停状态；只有点击继续才联网。已下载未启用的组件重启后保持关闭。
5. 下载期间导入音频仍以 CPU 完成；组件检查通过之后开始的任务使用 NVIDIA GPU，正在执行的 CPU 任务不重启。
6. 控制台必须分别出现归档校验、cuBLAS 矩阵运算通过、cuDNN 卷积运算通过。只有这两项真实运算均通过才能显示已启用。
7. 在没有系统 CUDA SDK / PATH 配置的机器上验收；确认能够定位应用数据目录中的运行库，避免继续依赖手动安装的 DLL。
8. 关闭加速后文件仍保留、之后任务使用 CPU；再启用只做本地检查，不重复下载。当前 GPU 任务不中断。
9. 让显卡识别失败或显存不足：本条任务最多回退 CPU 一次，下一条直接 CPU；设置页显示暂不可用，可重新检查。旧任务的失败不能覆盖之后完成的新检查。
10. 损坏归档、损坏已安装文件、磁盘空间不足、杀毒软件阻止 DLL、过旧驱动分别核对错误状态和控制台原因；损坏文件不能显示已启用。
11. 同开两个窗口，下载操作不能并发；另一窗口暂停可以生效。强制结束操作所属窗口后，剩余窗口能恢复暂停状态，不自动续传。
12. 720×480、960×640、系统字体放大下检查新区域的换行、按钮边框、键盘焦点、进度显示；其他页面保持原有精简布局。

## 核心流程

1. 首次进入上传页只有上传区域。在没有默认模型时导入一段中文录音：自动进入“我的音频”，出现“等待模型”。
2. 在模型设置下载 Small 并设为默认，回到列表：原任务应自动转录，无需再次上传。
3. 完成后显示“已完成”和“查看结果”；核对文字、时间戳、全文复制和系统打开音频。
4. 第一条转录时继续导入第二条：第二条显示“排队中”，先后执行，不同时加载两个模型。
5. 转录过程中切换所有页面，任务不中断。后台阶段更新不抢焦点，展开的原因仍可阅读。
6. 取消排队任务不启动识别。取消进行中的任务应停止子进程，最终显示“已取消”；可以重试。
7. 损坏音频、伪装扩展名、无法解码音轨应显示“转录失败”和原因，保留文件；无语音的有效音频允许完成并显示“未识别到语音”。
8. 缺少识别 Python 包或运行库时，应说明失败原因。NVIDIA 初始化错误、显存不足或 GPU 进程异常时只回退 CPU 一次，不能无限重试。
9. Mac M5 实际确认使用 Apple GPU。Windows CPU 与 GPU 分别记录相同录音的耗时、内存 / 显存和结果差异；不要用一种设备的测试替代另一种。
10. 长录音、中文夹英文、静音较多、噪声和多人录音分别核对漏字、重复、幻觉及时间戳。当前不区分说话人。

## 持久化与竞争

1. 转录完成后重启，历史和文字仍可查看；移动原始文件不影响应用副本。
2. 转录中正常关闭应用，再次打开后重新排队并处理整条音频。
3. 强制结束应用后重新启动：任务不能永远停留在“转录中”；旧子进程应退出，模型锁最终释放。
4. 同一环境开启两个实例，只允许一个实例调度转录；在另一个窗口取消也应生效。
5. 接近转录完成时取消：只允许“已完成”或“已取消”之一，不出现已取消后又被迟到结果覆盖。
6. 转录中不能直接删除音频；取消结束后再删除，音频副本、任务与结果同时从列表消失，原文件保留。
7. 删除后立即刷新和重启，不应因迟到的进度 / 结果重新出现记录。
8. 导入后修改默认模型，已有模型绑定的任务仍使用原模型；失败 / 取消后重试使用新的默认选择。
9. 测试导入中取消、关闭、数据库提交失败：不得出现半个音频的转录任务。已有 v3 历史记录升级后加入任务队列。
10. 删除数据库事务失败应恢复文件；提交成功但待清理文件 unlink 失败，记录保持删除，下次启动清理残留。

## 模型资源与界面

1. 旧 `.pt` 存在时，不能直接显示新引擎“已安装”；下载新格式后旧文件仍存在。
2. Windows 模型目录含 CTranslate2 权重、配置、词表 / tokenizer；Mac 含 MLX 权重和配置，均有完整清单。
3. 下载进度依据清单总大小和实际接收字节；暂停、网络中断和重启后可以继续。校验失败不能进入已安装状态。
4. 缺少某个配置或权重文件时刷新，应要求重新下载。
5. 正在转录的模型不能被删除，界面说明占用；结束后重试可删除。
6. 明确删除模型时同时清理旧格式及未完成下载；成功后取消默认选择。
7. Apple Speech 保留原来的系统查询 / 下载，不能被选为本版自动转录默认模型。
8. 720×480、960×640 和放大字体下核对表格滚动、长文件名、状态和按钮；列表页没有多余标题、说明或添加音频按钮。
9. 列表轮询和用户操作请求串行，不因为轮询吞掉点击；离开列表停止轮询，回到列表立即读取最新状态。
10. 音频记录 / 错误文本中的 HTML 字符只能作为文字显示。查看结果后快速切页，迟到响应不能切回结果页。

## 控制台日志

1. 从终端启动后应立即输出平台、Python 版本、数据目录和识别引擎；每条日志包含时间、级别和 PID。
2. 导入并转录一段音频，用任务 ID 对照主进程与识别子进程日志，确认能看到解码、CUDA 设备数 / Apple GPU、模型加载、耗时及结果保存。
3. GPU 失败时应输出原始错误与回退原因；子进程异常退出时输出退出码。取消和正常关闭也应有结束日志。
4. 日志不包含音频数据或转录正文；轮询和成功的音频分块不刷屏。设置 `SONA_LOG_LEVEL=DEBUG` 后可查看更详细的进度事件。
